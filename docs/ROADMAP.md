# نقشه راه و ریسک‌ها

وضعیت: پیشنهاد برای تأیید؛ آغاز هر فاز منوط به تأیید ادامه از طرف کاربر است. فازهای میانی بخشی از محصول کامل‌اند، نه جایگزین نیازمندی‌های باقی‌مانده. ترتیب، وابستگی است؛ زمان قطعی بدون مشاهده داده و نتیجه فاز قبل وعده داده نمی‌شود.

هر فاز: محدوده دقیق کوچک → پیاده‌سازی → آزمون مرتبط → رفع شکست → اصلاح اسناد/DECISIONS → ثبت نتیجه در PROGRESS → گزارش به کاربر → انتظار تأیید فاز بعد. اگر یک فاز در عمل بزرگ بود، قبل از اجرا به زیر‌فازهای قابل پذیرش تقسیم شود؛ کار نیمه‌تمام «تمام‌شده» ثبت نشود. آزمون‌پذیری و امنیت به فاز پایانی موکول نمی‌شوند.

## معیار کارایی پیشنهادی

پس از تعیین سخت‌افزار، fixture حداقل ۱۰٬۰۰۰ عملیات و چندصد lot برای بررسی تجربه تهیه شود. هدف اولیه پیشنهادی: ثبت عملیات رایج و داشبورد گرم معمولاً زیر یک ثانیه روی دستگاه کاربر؛ این وعده اندازه‌گیری‌شده فعلی نیست. صحت بر cache مقدم است. index و query بررسی شوند؛ cache نسخه‌دار فقط اگر اندازه‌گیری نیاز نشان داد. محاسبات طولانی پیشرفت و امکان ازسرگیری دارند و نباید قفل نوشتن را تا پایان export نگه دارند.
