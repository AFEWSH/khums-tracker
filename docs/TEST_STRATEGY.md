# برنامه تست و اعتبارسنجی

## اجرای آزمون فاز ۶ — 2026-10-14

آزمون مستقل I01–I04 برای فرمول خالص با داده ساختگی و بدون float، و آزمون feature برای سری/نقطه/اصلاح، روزهای ماه شمسی، تکرار CSV، rollback و کنترل دسترسی اضافه شد. I05–I09 مربوط به اتصال واقعی دامنه مالی، نقص CPI، سری ناسازگار و گزارش نهایی هنوز کامل نیستند و نباید موفق گزارش شوند. Q09 پیش از نتیجه اقتصادی نهایی لازم است.


## فاز ۵ب — 2026-10-14

B05/B06 برای CSV نقدی با fixture مستقل پوشش دارند: ریال/تومان دقیق، تاریخ شمسی/میلادی، آپلود Livewire، مرجع تکراری بی‌اثر، تعارض payload، شباهت محتوایی، formula rejection، rollback خطای میانه batch، تغییر revision پس از preview و دسترسی خصوصی. XLSX در این فاز پیاده/آزموده نمی‌شود؛ اجرای B06 برای XLSX در فاز ۱۰ منوط به انتخاب بسته سازگار است.


## وضعیت اجرایی فاز ۴/۵ — 2026-10-14

آزمون اجرایی فاز ۴/۵ شامل FIFO جزئی و کامل، فروش سود/زیان، تبدیل، ثبت خرید/فروش/تبدیل و درآمد/هزینه/انتقال تاریخ‌گذشته، تغییر بهای فروش بعدی، رد کسری بعدی و rollback کامل، اصلاح نقدی و ارزش دارایی افتتاحیه، fact پیش از افتتاحیه، پوشش صریح و جریان نقدی بدون دوباره‌شماری انتقال است. fixtureهای B01/B02 و آزمون‌های ۸۳گانه فعلی با DB موقت موفق‌اند. آزمون اصلاح مقدار/اظهار مخمّس، rollback در کسری فروش بعدی، تسویهٔ جزئی/کامل طلب ارزی و رد بدهی بیش از نقد نیز افزوده شدند. آزمون SQLite با دو اتصال مستقل قفل نویسنده/کلید یکتا/عدم فروش بیش از مانده را در سطح DB می‌سنجد؛ آزمون رقابت end-to-end دو درخواست HTTP و مرور بصری همچنان محدودیت پذیرش‌اند.


## آزمون اجرایی فاز ۴ — 2026-10-14

`QuantityAssetsTest` با داده ساختگی، O03/O06/O10 (افتتاحیه مقداری و تعهد ارزی)، بهای افتتاحیه مستقل از بهای تاریخی، خرید با کارمزد یک‌باره، idempotency، رد کسری نقد، تاریخ قیمت بدون آینده‌نگری، نسخه قیمت، rollback هنگام شکست quantity، authorization و خطای دقت عددی در Livewire را می‌آزماید. تست فاز ۳ برای برگشت نقدی به‌روزرسانی شد تا سند دارایی را برنگرداند. F04–F08/F14–F16 و S05 برای فروش/تبدیل و رقابت موجودی هنوز اجرا نشده‌اند؛ تا تأیید FIFO و تکمیل کد، دروازه فاز ۴ کامل نیست. `SqliteBackupTest` schema ۳ را نیز بازیابی می‌کند.

اجرای فاز ۳ در 2026-10-14: آزمون‌های Feature `CashFinanceTest` و Unit `CashWriteLockTest` اضافه شدند. نمونه‌های F09 (انتقال بدون درآمد)، F12 (اصل قرض/طلب)، F13 (درآمد تعهدی یک‌بار)، F17 (برگشت سند آخر)، F19/O01/O02/O05/O09 (افتتاحیه مخمّس اعلام‌شده/unknown، نسخه و تکرار)، S03/S04/S12 (کلید تکرار، rollback تزریقی و retry) و قفل دو اتصال مستقل پوشش داده شدند. ثبت backdated قبل از آخرین سند عمداً رد می‌شود و F18/replay هنوز آزمون/قابلیت فاز ۵ است. آزمون کامل: ۵۷ تست/۳۲۳ assertion موفق؛ Build موفق. داده فقط ساختگی و DB تست in-memory/فایل موقت بود.

یادداشت اجرا 2026-10-14: suite واحد به `phpunit.xml` افزوده شد. شش تست فاز ۲ با ۳۲ assertion برای تبدیل تومان/ریال و overflow، گردکردن، تخصیص 100→34/33/33، مقدار ۱۸ رقم، تبدیل شمسی و UTC نامعلوم، و پشتیبان رمزدار/WAL/بازیابی به فایل خالی موفق‌اند. آزمون backup با SQLite فایل موقت، نویسنده همزمان و داده ساختگی اجرا شد؛ رمز غلط و backup ناقص رد شدند. تست کامل پروژه پس از افزودن suite واحد: ۴۳ تست/۲۴۸ assertion؛ فازهای دفترکل و احکام همچنان سناریوی آینده‌اند.

وضعیت: طرح آزمون کل محصول، به‌علاوه کد تست‌های فاز ۱. وابستگی‌ها نصب و ۳۷ تست Pest فاز ۱ با ۲۱۶ assertion موفق‌اند؛ نتایج و محدودیت مرورگر در PROGRESS هستند. سناریوهای مالی آینده همچنان طرح آزمون‌اند.

## لایه‌ها و استقلال نتیجه مورد انتظار

- Unit با Pest: Money/Quantity/Ratio، تبدیل تاریخ، تخصیص باقیمانده، انتخاب lot، موتور اقتصادی و هر rule مستقل؛ بدون DB و clock واقعی.
- Feature: auth/CSRF/authorization، فرم‌های Livewire، ثبت خرید/فروش/انتقال، قیمت/CPI، پیش‌نویس و بستن، گزارش و خروجی.
- Integration: DB اتمیک، دو اتصال همزمان، replay، snapshot، نسخه‌گذاری، backup/restore و سازگاری موتورهای DB. SQLite فایل واقعی برای concurrency؛ in-memory کافی نیست.
- آزمون پذیرش دستی با داده ساختگی فارسی: موبایل، RTL، صفحه‌کلید، PDF و مسیر بررسی سال. سناریوی مالی منتخب با محاسبه مستقل کاربر تطبیق می‌شود.

انتظار تست از سرویس تحت آزمون تولید نمی‌شود. fixture دستی و فایل golden دارای محاسبه روشن است؛ در فرمول‌های مالی یک محاسبه مستقل کسری مرجع استفاده می‌شود. seed/داده واقعی کاربر وارد مخزن نمی‌شود. clock، ترتیب و شناسه‌های مؤثر کنترل می‌شوند. تست روی DB واقعی کاربر اجرا نشود.

## دروازه پایان هر فاز

پس از scaffold، `php artisan test`/Pest مربوط، formatting مصوب (مثلاً Pint)، و برای تغییر frontend ساخت Vite اجرا می‌شوند. نام فرمان، محیط، نتیجه و محدودیت واقعی در PROGRESS ثبت شود. تست‌های concurrency/restore روی پایگاه موقت و پاک انجام شوند. سپس سناریوهای رگرسیون مرتبط؛ تست گسترده اضافی تنها با توجیه تغییر/ریسک.

پیش از محصول کامل: تمام مسیرهای حساس این سند، تست engineهای DB مقصد، آزمون بازیابی، خروجی فارسی و تطبیق عددی مستقل باید پاس شوند. پوشش خط به‌تنهایی معیار صحت نیست؛ شاخه‌های unknown، مرز دوره، زیان، payment و تداخل قواعد باید تست مستقیم داشته باشند. هر باگ مالی یک regression test رفتاری و اصلاح سند می‌گیرد.

## تست‌های اجراشده فاز ۱

سه فایل در tests/Feature شامل ۲۹ تعریف تست و datasetهای منفی‌اند؛ اجرای واقعی با datasetها ۳۷ تست/۲۱۶ assertion دارد و همه موفق‌اند. داده ساختگی و clock کنترل‌شده‌اند. برخلاف سناریوهای مالی آینده، این بخش کد و نتیجه اجرایی دارد.

| محدوده | فایل | رفتار مورد آزمون |
|---|---|---|
| ورود و خروج | AuthenticationTest.php | مهمان، ورود Livewire/POST، session rotation، رمز پاک‌شده، پیام عمومی، اعتبارسنجی، سقف پنج تلاش و cooldown، سقف IP، مالک غیرفعال/هویت دیگر، خروج فقط POST |
| فرمان مالک | OwnerCommandsTest.php | prompt رمز مخفی، hash صحیح، رد مالک دوم بدون overwrite، رمز ضعیف/نامعتبر/ناهمسان و reset با حذف نشست‌ها |
| امنیت و پایه | SecurityAndFoundationTest.php | RTL، escaping، cookie HttpOnly/Strict/expire، رمز payload نشست، headers/no-store، CSRF واقعی، update واقعی Livewire پس از خروج، FK و فقط جدول‌های هویت، مسیر فایل‌های خصوصی |

phpunit.xml APP_ENV=testing و DB_DATABASE=:memory: را force می‌کند؛ TestCase پس از bootstrap و پیش از RefreshDatabase اتصال غیرآزمایشی را رد می‌کند. این guard برای config cache قدیمی مهم است. CSRF در تست‌های خاص با تغییر محیط container به local از bypass تست خارج می‌شود؛ DB همچنان in-memory است. middleware در این تست‌ها حذف نشده است.

فرمان پس از نصب موفق: composer test (Pest). php artisan test نیز در صورت discovery بسته‌های test قابل استفاده است. فراخوانی‌های تحویل اولیه به نبود vendor برخورد کردند؛ پس از نصب، composer test بدون failure/warning موفق شد. Format/Build نیز از manifest پروژه اجرا و موفق شدند. پذیرش بصری عرض ۳۶۰/دسکتاپ و صفحه‌کلید به‌علت محدودیت اجرای مرورگر این نشست باقی است.

علاوه بر Pest، درخواست‌های GET/POST ورود با CSRF، dashboard خصوصی، logout و رد cookie نشست قبلی، در فرایندهای مستقل PHP از طریق HTTP kernel روی SQLite موقت آزموده شدند؛ موفق. این بررسی بدون اینترنت و بدون listener TCP اجرا شد و به‌معنی تعامل موفق مرورگر نیست. ابزارهای موقت در /tmp هستند و dependency تست جدیدی به پروژه اضافه نکردند.

bootstrap تست از .env.example عمومی استفاده می‌کند؛ وجود .env واقعی برای composer test لازم نیست. Root SQLite محلی و کلید آن با تست جایگزین نمی‌شوند. نمونه‌های پذیرش باقی‌مانده: ورود/خطای رمز با مرورگر، Tab/Enter، نبود overflow در عرض ۳۶۰، خوانایی فونت و اجرای صفحات با اینترنت قطع ولی سرور محلی روشن.
